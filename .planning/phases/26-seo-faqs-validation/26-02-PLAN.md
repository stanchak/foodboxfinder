**Affiliate population logic:**
```typescript
// Only set affiliateUrl if currently null
if (!provider.affiliateUrl && KNOWN_AFFILIATE_URLS[provider.slug]) {
  updateData.affiliateUrl = KNOWN_AFFILIATE_URLS[provider.slug];
  fieldsUpdated.push("affiliateUrl");
}
```

**Validation logic (template-based, no API needed):**
For each provider, validate:
1. `status` is not DISCONTINUED (if it is, skip and log)
2. `description` is not empty or stub ("see research notes")
3. `shortDescription` exists and is under 300 chars
4. `category` is a valid CategoryType enum value
5. At least one Plan record exists (log warning if missing)
6. `website` field is a valid URL format (starts with http)

Log validation warnings but do NOT auto-fix (too risky for batch). Instead, collect warnings in a summary report at the end.

**xAI validation (optional, when credits available):**
If `--template-only` is NOT set, use xAI to check if the provider website is still active and the category is still accurate. Prompt:
```
Visit ${website} and confirm:
1. Is this website still active and selling ${categoryLabel}?
2. Is the provider name still "${name}" or has it rebranded?
Return JSON: { "active": true/false, "rebranded": null or "new name", "notes": "any issues" }
```
On xAI failure (429, timeout), skip validation for that provider and just set lastVerifiedAt.

**lastVerifiedAt:** Set `lastVerifiedAt: new Date()` for ALL processed providers (per R26.5), regardless of whether xAI validation was used. The timestamp means "we checked this provider's data during v3.0".

**Database writes:**
```typescript
await prisma.provider.update({
  where: { id: provider.id },
  data: {
    ...updateData, // affiliateUrl if applicable
    lastVerifiedAt: new Date(),
  },
});
```

**Summary output:** Print totals: affiliateUrlsSet, lastVerifiedAtSet, validationWarnings, failed. Also print the validation warnings list so the user can review.
